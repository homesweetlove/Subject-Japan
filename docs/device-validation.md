# 네이티브 기기 검증

## 2026-10-19 소스 점검 결과 (실기기 미검증)

| 기능 | 소스에서 확인한 구현 | 아직 검증되지 않은 항목 |
| --- | --- | --- |
| 번역 | Android Kotlin / iOS Swift의 ML Kit 모듈과 양방향 provider 계약 | iPhone 실기기 모델 설치·오프라인 재시작·양방향 변환 |
| 카메라 OCR | Android ML Kit / iOS Vision, 이미지 선택 UI | 실제 사진의 회전·한/일 혼합 글씨·사진 권한 거부 |
| 음성 대화 | Android SpeechRecognizer / iOS Speech + AVAudioEngine, 전용 앱 분기 | 각 언어의 on-device 지원, 실제 마이크 권한, 중단·재개 |
| 교통카드 | Android NfcF / iOS Core NFC FeliCa, 0x090f 기록 읽기 | 실제 카드 종류와 기록 1~19건·20건·읽기 중 카드 제거·Apple entitlement |
| 로컬 알림 | Expo Notifications로 막차·여행 일정 예약, 웹에서는 미지원 | 실제 Android 절전/ iPhone 예약·재시작·탭 이동 동작 |
| 데이터 저장 | Android Room, iOS/Web AsyncStorage 계약 | 신규 버전 업그레이드·손상·중단 시 실제 데이터 보존 |

**NFC 주의:** 양쪽 네이티브 판독 루프는 기록을 최대 20블록까지 순서대로 읽고, 중간에 카드에서 오류를 받으면 현재는 스캔 전체가 실패할 수 있습니다. 실제 카드가 기록 20건 미만을 어떻게 응답하는지와, 안전하게 종료할 수 있는 상태 코드인지를 실기기로 확인하기 전에는 “1~20건 카드를 문제없이 읽는다”고 주장하지 않습니다. 잘못된 상태 응답을 마지막 기록으로 임의 간주해서도 안 됩니다.

**iOS 배포 주의:** `.github/workflows/native.yml`에는 iOS 시뮬레이터 빌드가 정의되어 있으나, 이것만으로 실물 FeliCa 읽기·실제 마이크 입력·Apple 서명 및 배포가 검증되지 않습니다. 이 문서를 수정하는 과정에서 네이티브 빌드나 실기기 테스트를 새로 실행한 것은 아닙니다.


JS 번들/웹 E2E는 실제 ML Kit 추론 검증을 대신하지 않습니다. 릴리스 전에 Android와 iPhone 각각에서 아래를 수행합니다.

1. 전용 빌드를 새로 설치합니다. 온보딩에서 사이즈 44를 저장합니다.
2. 네트워크 없이 사이즈 문장을 선택합니다. `この商品の44サイズはありますか？`가 나오는지 확인합니다.
3. 모델 미설치 상태에서 임의 문장을 입력합니다. 다운로드 안내가 나와야 합니다.
4. Wi-Fi에서 번역팩 다운로드를 완료합니다. 셀룰러만 연결했을 때 자동 다운로드하지 않아야 합니다.
5. 비행기 모드에서 문장팩에 없는 한국어/일본어 문장을 각각 번역합니다. 프로세스 종료 후에도 다시 작동해야 합니다.
6. 번역 중 입력 변경·탭 이동·프로필 이동을 반복해 오래된 결과가 덮어쓰지 않는지 확인합니다.
7. 복사한 일본어를 다른 앱에 붙여 넣고, 전체화면에서 긴 문장이 스크롤되는지 확인합니다.
8. 즐겨찾기, 최근 기록, 테마, 사이즈가 앱 재시작 후 유지되는지 확인합니다.
9. 사이즈 변경은 새 문장에 반영되고 이전 기록은 유지되는지 확인합니다.
10. VoiceOver/TalkBack, 큰 글꼴, 키보드, 작은 화면, 라이트/다크 모드를 확인합니다.
11. 저장 공간 부족/모델 다운로드 실패 후 재시도와 데이터 보존을 확인합니다.
12. 전체 삭제 후 앱을 재시작해 온보딩과 빈 데이터가 표시되는지 확인합니다. 언어 모델은 남습니다.

카메라 OCR·기기 내 음성 인식·실물 FeliCa NFC·위치 검색은 현재 소스에 구현되어 있습니다. 다만 **소스 구현 및 CI 빌드 설정의 존재가 Android/iPhone 실기기 통과를 의미하지는 않습니다.** 기기·OS·권한·Apple 서명·카드 조합에 대한 검증 결과는 아직 이 문서에 기록되어 있지 않습니다.

## Room·막차·가이드 추가 확인

1. 기존 Android 앱에서 사이즈·기록·쿠폰 저장 후 새 전용 빌드로 업데이트합니다. 앱을 삭제하지 않고 데이터가 Room으로 이전되는지 확인합니다.
2. 막차를 등록한 후 프로세스를 종료·재실행하고, 배경 상태에서 기다렸다 돌아와 카운트다운이 현재 시간으로 보정되는지 확인합니다.
3. 기기 시간대를 일본 이외로 바꾸어도 입력·표시 날짜가 JST인지 확인합니다. 자정 이후 입력과 지난 시각 종료 상태도 확인합니다.
4. 시간표·쿠폰·공연 링크가 기본 브라우저에서 열리는지 확인합니다. 체크리스트의 재시작 유지와 전체 삭제도 확인합니다.
5. Room 읽기·쓰기 실패 시 원본 데이터가 보존되고 오류가 표시되는지 확인합니다. 전용 앱은 저장 모듈 추가로 재빌드가 필요합니다.


## OCR·음성·교통카드·결제 추가 검증 (미실행 항목)

- 새 네이티브 빌드를 설치합니다. iPhone App ID의 NFC Tag Reading capability와 서명 권한을 확인합니다.
- 실물 Suica/PASMO/ICOCA를 각각 읽고 실제 역 단말 잔액·최근 기록과 비교합니다. 여러 카드, 이름 변경, 재스캔, 삭제, NFC 꺼짐, 중간 제거, 취소, 백그라운드 전환을 확인합니다.
- 일본어 메뉴판·세로 안내문·영수증·표지판, 한국어 사진, 회전된 사진, 사진 권한 제한/거부, 촬영 취소를 검사합니다. 원본 사진이 지워지지 않고 앱 캐시는 정리되는지 확인합니다.
- 한국어/일본어 음성, 기기 내 인식 미지원, 마이크 거부, 말하기 끝/취소, 전화 수신, 앱 전환을 확인합니다. 비행기 모드에서 모델 준비 후 실제 인식·번역을 확인합니다.
- 일본 현지 위치 권한 허용/거부, Overpass 네트워크 차단/시간 초과, 지점별 조건/지도 좌표를 확인합니다. 위치는 검색 버튼 전까지 요청/전송하지 않아야 합니다.
- PAY에서 매장 실제 영수증과 계산을 대조하되 단수 처리·수수료 기준 차이를 기록합니다. 11월 면세 환급 방식은 실제 매장 안내를 따릅니다.
- Room 업그레이드 후 카드·환율·일정이 유지되고 전체 초기화 시 모두 지워지는지 확인합니다.
