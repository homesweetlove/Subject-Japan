# 로컬 데이터 처리

## 수집 범위와 목적

- 닉네임: 화면 개인화. 선택 입력이며 실명이 필요하지 않습니다.
- 상의·하의·신발 사이즈: 쇼핑 문장에 사용자가 저장한 표기를 치환합니다.
- 번역 원문·번역문·시각: 최근 기록과 즐겨찾기를 다시 사용하기 위해 저장합니다.
- 교통카드 IDm·별칭·마지막 읽기 시각·최근 20개 잔액 기록: 최대 20장, 서버 전송 없음. IDm은 카드별 재인식에 사용하며 결제 계좌번호가 아닙니다.
- 멤버십 이름·정적 바코드 번호·사진에서 인식한 QR 또는 바코드 패턴·HTTPS 링크·메모: 최대 40개, 로컬 저장. 동적 QR·계정 비밀번호·카드 결제정보는 저장하지 마세요.
- 환율·출처·기준일·가져온 시각, 일정·예약번호·메모·완료 체크: 로컬 저장. 예약번호는 사용자가 직접 입력한 경우만 보관합니다.
- 테마·온보딩 상태: 앱 재실행 시 선택을 유지합니다.
- 저장한 쿠폰·혜택 ID: 관심 혜택을 다시 찾기 위해 기기에만 저장합니다 (최대 200개).
- 공항 노선·출발역·터미널·사용자가 확인한 출발 시각·여유 시간·확인 시각: 막차 타이머 최대 12개.
- 공연·게스트 카드 준비 체크 상태: 다음 실행 시 준비 진행도를 복원합니다.

Android 전용 앱은 `subject-japan-local.db`의 Room `local_documents` 테이블에 전체 상태 문서를 저장합니다. iOS·Expo Go·웹은 `subject-japan.local.v1` AsyncStorage 키를 사용합니다. Android 업데이트 시 기존 상태를 검증하고 Room 저장 성공 후 이전 키를 지웁니다. Room 오류 시 예전 데이터로 조용히 되돌아가 덮어쓰지 않습니다. 앱이 자체 서버로 이 데이터를 전송하지 않습니다. 번역은 ML Kit 기기 내 추론을 사용하며 Google 모델 다운로드 및 SDK 진단 통신은 별개입니다.

기록 100개를 넘으면 가장 오래된 최근 기록을 제거합니다. 즐겨찾기는 기록과 별도로 보존하고 100개 초과 시 기존 항목 삭제를 안내합니다. 프로필 사이즈 변경이 이전 번역 기록의 내용을 바꾸지는 않습니다.

## 사용자 제어

- 첫 실행 입력을 건너뛰어도 앱을 쓸 수 있습니다.
- 사용자 페이지에서 언제든 사이즈를 수정하거나 비울 수 있습니다.
- 최근 기록 삭제는 즐겨찾기를 유지합니다.
- 사용자 페이지의 전체 삭제는 확인 후 프로필·사이즈·기록·즐겨찾기·교통카드·환율·일정·저장한 혜택·막차·체크리스트·설정을 하나의 상태 변경으로 초기화합니다.
- 멤버십과 여행 QR은 전체 삭제·클립보드 백업/복원 대상이며 각 카드에서도 삭제할 수 있습니다. 스캔은 기기에서 처리하며 백업에 코드 패턴이 포함됩니다.
- 전체 삭제 후에도 ML Kit 언어 모델 파일은 다시 사용할 수 있도록 기기에 남습니다. 앱 삭제 시 모델을 포함한 앱 데이터가 제거됩니다.
- 앱 삭제/기기 변경 후 복구용 계정 서버는 없습니다.

Android 앱 백업은 `allowBackup: false`로 설정합니다. iOS는 `RCTAsyncStorageExcludeFromBackup: true`로 AsyncStorage의 iCloud 백업 제외를 명시합니다. 운영체제·제조사에 따른 기기 전송 정책은 출시 디바이스에서 확인해야 합니다. 웹 미리보기는 해당 브라우저의 localStorage를 사용하므로 공용 브라우저 사용 후 전체 삭제를 권장합니다.

Room과 AsyncStorage는 이 앱에서 별도 암호화하지 않습니다. 앱 샌드박스/기기 보안에 의존하며 자격증명·여권·카드번호를 저장하도록 설계하지 않았습니다. 클립보드 복사는 사용자가 누른 경우에만 수행하며 이후 클립보드 처리는 OS 설정에 따릅니다. `여행 > 디지털 & 백업`의 데이터 백업은 프로필·기록·예약번호를 포함한 전체 상태를 클립보드에 복사하므로, 화면에서 다른 앱·키보드·클립보드 동기화 노출 위험을 안내하고 1분 뒤 클립보드 내용이 그대로면 지웁니다. 백업 복원은 저장소와 같은 검증(버전·필드 형식·길이·개수 제한, 최대 1,000,000자)을 통과한 데이터만 요약을 보여 준 뒤 사용자가 확인할 때 현재 데이터를 대체하고 클립보드를 비웁니다. 일반 초기화는 앱 상태 삭제이며 저장 매체의 포렌식 삭제를 보장하지 않습니다.

## 네트워크·권한과 외부 서비스

쿠폰 카탈로그 열람·검색·저장은 네트워크를 사용하지 않습니다. 사용자가 공식 링크를 누르면 외부 브라우저에서 해당 사이트를 방문하므로 이후 통신과 회원가입은 해당 사업자의 정책을 따릅니다. Subject Japan은 프로필·사이즈·검색어·저장 목록을 링크에 포함하지 않으며 여권, 국적, 입국일, 매장 계정 정보를 수집하지 않습니다.

쿠폰 화면에서 **쿠폰 혜택 새로고침**을 누르거나 **탭을 열 때 자동 새로고침**을 켜면 GitHub의 공개 카탈로그(raw.githubusercontent.com)와 외부 상태 제공처(`subject-japan-data.vercel.app`, 빌드 시 HTTPS 주소 변경 가능)에 요청을 보냅니다. 프로필·쿠폰 검색어·저장 목록·위치는 전송하지 않습니다. 외부 서버에는 접속 IP 등의 통신 정보가 남을 수 있으며 상태 조회 실패 시 저장된 목록을 그대로 보여 줍니다. 서버의 확인 결과가 실제 쿠폰 사용을 보장하지 않습니다.

PAY 화면의 Android 가격표·영수증 금액 추출은 기존 기기 내 OCR을 재사용합니다. 후보값만 잠시 표시하고 사용자가 명시적으로 선택해야 숫자 입력란에 적용됩니다. 카메라·갤러리 원본은 삭제하지 않고 자동으로 영수증을 저장하지 않습니다.

사진 OCR은 Android ML Kit 번들 모델 또는 iOS Vision으로 처리하며 업로드하지 않습니다. 사진 선택기가 앱 캐시에 만든 파일은 OCR 완료/화면 이탈 시 삭제를 시도합니다. 사용자의 원본 사진은 지우지 않습니다. 강제 종료 시 남은 앱 임시 파일은 OS 캐시 정책을 따릅니다. 인식 문장은 편집 화면에만 있고 번역 버튼을 누른 뒤 원문·번역문이 최근 기록으로 저장됩니다.

음성은 기기 내 인식을 강제하고 앱이 녹음 파일을 보관하지 않습니다. iOS 음성 인식/마이크 권한, Android 마이크 권한은 사용 시 요청합니다. 지원하지 않는 경우 클라우드 인식으로 전환하지 않습니다. 음성 읽기는 사용자가 누를 때 시스템 TTS를 사용하며 기기 음성 서비스의 다운로드/네트워크 정책을 따릅니다.

환율 가져오기를 누를 때 Frankfurter에 JPY/KRW 조회를 보냅니다. PAY의 `자동 최신화`는 기본으로 꺼져 있으며, 사용자가 켠 경우에만 PAY 화면을 열 때 저장된 환율이 6시간보다 오래됐으면 같은 조회를 보냅니다. 서버 응답은 100엔당 200~5,000원 범위를 벗어나면 저장하지 않습니다. 상품 금액·할인·사용자 데이터를 보내지 않습니다. 날씨는 사용자가 `오늘` 탭에서 도시를 고른 뒤에만 일본 기상청(`www.jma.go.jp/bosai`)에서 해당 도시의 고정된 예보 구역 파일과 AMeDAS 관측소 파일(현재 기온)을 받아 옵니다. 요청 URL에는 도시별 고정 코드만 들어가며 기기 위치·사용자 데이터는 보내지 않습니다. 마지막 예보를 30분 동안 로컬에 캐시해 오프라인에서도 보여 줍니다. 기상청 홈페이지 콘텐츠는 출처 표시 조건으로 상업적 이용을 포함해 무료로 쓸 수 있으며(CC BY 4.0 호환), 앱은 `출처: 気象庁ホームページ`와 가공 사실을 화면에 표시합니다. 다만 `bosai` JSON은 공식 문서화된 API가 아니어서 형식이 바뀔 수 있으므로, 응답을 엄격히 검증하고 실패 시 오류 안내만 표시합니다. 막차·일정 알림은 `expo-notifications`의 기기 내 예약 알림만 사용하며 푸시 토큰 발급·서버 전송을 하지 않습니다. 알림 문구는 잠금화면에 보일 수 있어 일정 제목·시각과 막차 역·공항·시각만 담고 예약번호·메모·주소는 넣지 않습니다. 주변 매장 검색은 별도 동의 버튼과 OS 위치 권한을 거쳐 약 100m 단위 좌표를 `overpass-api.de`에 전송합니다. 위치·매장 결과는 저장하지 않으며 백그라운드 추적하지 않습니다. 지도 열기는 선택한 장소/매장 좌표를 Google Maps에 전달합니다. 위치 권한 없는 지역·매장 검색은 선택한 지역과 입력한 매장명만 Google Maps에 전달합니다. 외부 서비스는 접속 IP 등 통신 정보를 처리할 수 있습니다.

인증 프로필과 로컬 쇼핑 프로필을 분리합니다. 클라우드 번역 제공자를 추가한다면 전송되는 원문과 제공자를 명확히 표시하고, 현재의 기기 내 처리 안내를 그대로 재사용하지 않습니다.
